# 애니어그램 유형 테스트

한국어 애니어그램 검사. 랜딩에서는 가볍게 시작하고, 결과를 본 뒤 원할 때만 더 자세한 질문을 이어간다. Next.js(App Router)
+ TypeScript + Tailwind CSS, 백엔드·DB·인증 없음. 응답은 서버로 전송되지 않으며 브라우저를
벗어나지 않는다.

> 이 검사는 **교육·자기이해 목적**이며 임상적 진단이 아니다.
> 윙은 측정된 결과가 아니라 **이론적 해석**이다.

문항 출처와 저작권 근거는 [`docs/sources.md`](docs/sources.md), 독립 저작권 리뷰
기록은 [`docs/item-review.md`](docs/item-review.md)에 있다.

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # vitest
npm run lint     # eslint (next lint는 15.3에서 deprecated, 16에서 제거됨)
npx tsc --noEmit
```

## 문항 제시 순서

`data/questions.ts`는 아홉 유형 모듈을 **이어 붙이지 않고 엮는다**.

```
라운드 r(0…9) 안에서 유형 t(0…8)를 차례로 돌며, t의 (r + 3t) mod 10 번째 문항
```

- 인접한 두 문항의 **유형이 절대 같지 않다**(라운드 경계 포함).
- `gcd(3, 10) = 1`이므로 유형마다 10문항이 정확히 한 번씩 쓰인다.
- 보폭 3은 facet 축(동기·두려움·주의 초점·관계·부하)까지 흩는다 —
  인접한 두 문항이 같은 축인 경우가 90문항 통틀어 **0쌍**이다.
- 순서는 **결정적**이다. 무작위 셔플이 아니므로 기계·실행·사용자에 따라 달라지지
  않고, `sessionStorage` 복원과 문항 세트 서명이 성립한다.

이전 순서는 모듈을 그대로 이어 붙인 `q1-01 … q1-10, q2-01 …`이었고, 화면이 10문항씩
묶어 보여 주므로 **한 묶음이 정확히 한 유형**이 됐다. 열 문장을 연달아 읽으면
응답자는 문항이 아니라 자기 개념에 답하게 되고(응답 세트), 묶음 첫 문항이 나머지의
기준선이 된다(후광 효과). 순서 불변식은 `lib/scoring.test.ts`가 지킨다.

## 기본 검사와 자세히 이어보기

랜딩에는 문항 수를 선택하는 두 경로를 두지 않는다. 모든 사용자는 `/test`에서 가볍게
시작하며, 실제 진행 화면에서만 `n/27`로 총량을 확인한다. 기본 결과를 본 뒤 더 자세히
살펴보고 싶은 사람은 이미 답한 문항을 제외한 나머지 질문을 이어간다.

| | 기본 검사 | 자세히 이어보기 |
| --- | --- | --- |
| 진입 | `/test` | 기본 결과의 이어하기 CTA |
| 유형당 | 3문항 | 완료 시 총 10문항 |
| 유형 점수 | **3~15** | 완료 시 **10~50** |
| 코드 버전 바이트 | `3` | `1` |
| 사용자 노출 | 랜딩의 단일 시작 경로 | 결과 화면에서만 제안 |

`/test?full`은 기존 직접 진입 호환성을 위해 계속 동작하지만 랜딩에서는 연결하지 않는다.
기존 버전 2의 45문항 공유 결과도 계속 해석한다. 어느 경로도 표준화·타당화된 정확도를
보장하지 않는다.

### 이어하기 — 이미 답한 문항은 다시 묻지 않는다

응답은 언제나 길이 90의 배열 하나이고, 기본 검사는 그중 27칸만 채운다. 이어하기는
나머지 63칸만 묻는다.

```
/test        → 기본 검사 → 결과
                         └ "더 자세히 알아보기" → /test?continue
                                                   → 남은 질문 → 자세한 결과
/test?full   → 기존 호환용 전체 검사 → 자세한 결과
```

세 진행 계획(`BASE_PLAN` / `CONTINUE_PLAN` / `FULL_PLAN`)은 `data/questions.ts`가 계산한다.
`BASE_PLAN`과 `CONTINUE_PLAN`은 서로소이고 합집합이 90칸 전부라 같은 문항을 두 번 묻지
않는다. 저장본 없이 `/test?continue`로 들어오면 채점 가능한 응답을 만들기 위해 기본
검사로 되돌린다.

## 채점 규칙

유형당 `n`문항 × 5점 리커트 → 유형 점수 **`n`~`5n`**. 기본 검사는 n=3 → 3~15,
전체 검사는 n=10 → 10~50이다. 기존 45문항 결과만 호환 척도 5~25를 유지한다.

### 역채점

`reverse: true` 문항(유형당 2개, 전체 18개)은 응답값 `v` 대신 **`6 - v`** 를 더한다
(1→5, 2→4, 3→3, 4→2, 5→1). 묵종 편향 방어책이다.

역채점 문항도 문항당 1~5를 기여하므로 **유형 점수 범위는 10~50 그대로**다.
따라서 공유 코드의 1바이트/유형 인코딩은 영향을 받지 않는다.

### 인접(adjacency)

애니어그램 원은 순환이다. 유형 `n`의 인접 유형은 `(n+7)%9+1`(이전)과 `n%9+1`(다음)이며,
**인접합 = 두 인접 유형 점수의 합**이다. **자기 점수는 포함하지 않는다.**
유형 1의 인접은 9와 2, 유형 9의 인접은 8과 1이다.

### 주유형 동점 규칙 — 결정적 필터 체인

pairwise 비교가 아니라 **남은 후보 집합 전체**에 순차 적용한다.

1. `후보 = argmax(점수)`
2. `|후보| > 1`이면 `후보 = argmax(인접합)` — 남은 후보 집합에 대해서만
3. 여전히 `|후보| > 1`이면 `min(유형 번호)`

### 윙 동점 규칙

윙은 주유형의 인접 두 유형 중 **고득점** 쪽이다.
**동점이면 순환 `n-1` 쪽을 채택한다**(회전 대칭 보존).
따라서 주유형 1의 동점은 `1w9`, 주유형 9의 동점은 `9w8`이다.
표기는 언제나 `^[1-9]w[1-9]$`를 만족하고, 윙은 언제나 주유형의 인접 유형이다.

### 모호성 안내

`1위 − 2위 < 3`(10~50 척도의 절대 점수차)이면 "유형이 뚜렷하지 않음"을 안내한다.
임계값 3은 리커트 한 칸(1점) 수준의 흔들림으로 순위가 뒤집히지 않는 최소선으로 고른
값이며 통계적으로 유도된 컷오프가 아니다. 이 검사는 1위와 2위만 본다.

45문항의 임계값은 **2**다. **같은 비율을 유지한 값**이다 — 90문항의 3점은 폭 41(10~50)
위의 값이고, 45문항의 폭은 21(5~25)이므로 `3 × 21 / 41 ≈ 1.5`, 정수로 올려 2다. 같은
절대값 3을 그대로 쓰면 폭이 절반인 척도에서 두 배로 관대해진다. 임계값이 결과 종류에
따라 갈린다는 사실은 `lib/scoring.test.ts`가 고정한다.

규칙의 정본은 이 문서와 [`lib/scoring.ts`](lib/scoring.ts) 주석 두 곳에 동일하게 기록된다.

## 결과 공유 URL

`/result/{code}`, `code = "{wing}-{base64url}"` — 예: `/result/5w4-AQoUHigyPEZQTA`.

- 페이로드는 **10바이트** = 버전 1바이트 + 유형 1~9 점수 각 1바이트.
- base64url 무패딩 14자 + 접두사 3자 + `-` = **총 18자**(항상 20자 이하).
- 링크만으로 결과가 완전히 복원된다. 서버 조회도, 저장된 상태도 없다.

디코드는 ① 형식 ② 버전 ③ 점수 범위 ④ **접두사–점수 일치** 중 하나라도
어긋나면 실패하고, 실패는 404다. 접두사는 URL 가독성을 위한 것이며, 디코드가 실패한
코드를 접두사만으로 렌더하지 않는다.

### 체크섬을 두지 않는 이유

**유효 범위 안의 변조는 탐지 대상이 아니다.** 이 URL은 사용자 본인의 결과이므로
지킬 신뢰 경계가 없다 — 점수를 고쳐 얻는 것은 자기 결과의 다른 버전뿐이고, 서버에
기록되는 것도 타인에게 권한을 주는 것도 없다. 접두사–점수 일치 검증만으로 무작위
문자열은 사실상 전부 거부되므로 체크섬 바이트는 비용만 늘린다.

### 버전 바이트 = 문항 세트

| 버전 | 문항 세트 | 유형당 문항 | 점수 범위 |
| --- | --- | --- | --- |
| `1` | 전체 90문항 | 10 | 10~50 |
| `2` | 기본 45문항 | 5 | 5~25 |

**45문항 결과와 90문항 결과는 다른 것이다.** 버전 바이트가 세트를 가리키고 점수 범위
검증도 그 세트의 범위로 하므로, 한쪽 점수를 다른 쪽 버전으로 읽히게 만든 코드는
디코드 단계에서 거부된다(404). 디코드된 세트는 결과 화면이 어느 경로의 결과인지 밝히고
45문항 한계 고지를 띄우는 근거가 되며, 두 종류 모두 `code.length <= 20`을 그대로
지킨다(언제나 18자).

버전 바이트는 **채점 규칙 + 문항 세트**를 가리킨다. 동점 규칙이나 문항 세트를 바꾸면
버전을 올려야 하며, **그 순간 기존 공유 링크는 무효가 된다**(구버전 코드는 404).
DB를 두지 않는 대가이고, 이 제품은 링크 영속성을 약속하지 않는다.
