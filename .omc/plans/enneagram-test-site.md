## 1. Requirements Summary

**목표**: 공개 라이선스 척도 + 애니어그램 이론 문헌을 근거로 구성한 **90문항(유형당 정확히 10문항) 한국어 검사**를 Next.js App Router 사이트로 만들어 Vercel에 배포. 응시자는 주유형 + 윙(`5w4`) + 9유형 점수 분포를 보고, **URL 링크**와 **PNG 카드**로 공유한다.

**확정 스택**: Next.js (App Router) + TypeScript + Tailwind CSS. SSG 중심. 백엔드/DB/인증 없음. 배포 대상 Vercel.

**확정 제약**
- 응답 데이터는 서버에 저장하지 않는다 (브라우저 메모리/`sessionStorage`까지만).
- **저작권**: RHETI, WEPSS 등 상용 표준 검사 문항을 복제하지 않는다. 문항은 (a) 공개 라이선스/퍼블릭 도메인 척도 기반 또는 (b) 이론 문헌 기반 자체 작성이며, 문항마다 출처 식별자를 데이터에 기록한다.
- 결과 공유 URL은 **경로 기반(스펙 line 41)이며, 서버 상태(DB·세션·저장소)에 의존하지 않는다**. 스펙 line 41의 "정적 경로 기반이어야 하며"는 구속력 있는 제약으로 취급한다. §3이 채택한 `/result/[code]` 단일 동적 세그먼트가 이와 양립하는 근거는 **스펙 line 77**이다 — line 77은 "정적 경로 + 쿼리 또는 base64url 세그먼트"를 명시적으로 허용한다. 즉 line 41은 *쿼리스트링 전용 설계*(A3)를 배제하는 조항이고, base64url 세그먼트는 line 77이 직접 승인한다. (이전 판이 line 41을 "철회"한 것은 오류였다 — 같은 조항을 A3 기각의 근거로 쓰면서 A1을 정당화할 때만 비구속으로 취급할 수는 없다.)
- 한국어 단일 언어, 모바일 우선 반응형.

**Non-Goals**: 응답 저장/통계 대시보드/재방문 이력, 로그인, 통합·분열 화살표, 본능 변형(sp/so/sx), 다국어, 임상적 진단 주장.

**성공 판정의 1순위**: "문항과 출처의 질". "간단하게"는 **인프라**에만 적용되는 제약이지 콘텐츠 분량에 적용되지 않는다 (인터뷰 Round 4에서 확정).

## 2. RALPLAN-DR Summary

### Principles (P1–P5)

- **P1. 콘텐츠가 제품이다.** 90문항과 그 출처 문서가 이 프로젝트의 핵심 산출물이다. 코드는 그것을 담는 그릇이다. 따라서 문항 리서치가 UI보다 **먼저** 실행된다.
- **P2. 법적 안전이 기능보다 우선한다.** 출처 없는 문항은 단 한 개도 데이터에 들어가지 않는다. 상용 검사 문항의 축자 복제는 물론, 번역/경미한 개작(paraphrase)도 금지한다. **이 원칙은 선언이 아니라 Step 2.5의 독립 리뷰 패스 + `copyrightReview` 필수 필드 + AC-14로 강제된다.**
- **P3. 인프라는 최소, 콘텐츠는 최대.** 런타임 상태 0, DB 0, 인증 0, 런타임 의존성은 Next.js가 기본 제공하는 것(`next/og`)만 사용한다. 새 npm 의존성은 "없으면 요구사항을 충족할 수 없음"이 증명될 때만 추가한다.
- **P4. 결과는 URL에 자족적으로 담긴다.** 링크를 받은 사람의 브라우저가 서버 조회 없이 결과를 완전히 재구성할 수 있어야 한다.
- **P5. 렌더링 경로는 하나.** 공유 미리보기(OG)와 다운로드 PNG는 같은 카드 컴포넌트에서 나온다. **실행 시점(빌드 타임 vs 런타임)이 달라도 컴포넌트와 렌더러가 같으면 P5를 만족한다.**

### Decision Drivers (top 3)

- **D1. 저작권 방어 가능성** — 모든 문항이 추적 가능한 출처를 갖고, **독립 리뷰어가 비복제 판정을 기록**했는가. (AC-2, AC-3, AC-14. 실패 시 프로젝트 자체가 배포 불가)
- **D2. 링크 재현성 + 카카오톡 공유 품질** — 링크만으로 결과가 100% 복원되고, 유형별 미리보기 카드가 뜨는가. (AC-9, AC-10)
- **D3. 인프라 단순성** — 백엔드/DB 없이, 추가 인프라 구성 없이 `vercel deploy` 한 번으로 끝나는가. (AC-12, AC-13)

### Viable Options

#### 결정 A — 결과를 공유 URL에 인코딩하는 방식

| | A1. base64url 페이로드 (`/result/5w4-<payload>`) | A2. 유형 전용 정적 경로 (`/result/5w4`) | A3. 전체 점수 쿼리스트링 (`/result?s=32,28,...`) |
|---|---|---|---|
| **Pros** | 9유형 점수까지 완전 복원 → AC-9 문자 그대로 충족. **스펙 line 77이 "정적 경로 + base64url 세그먼트"를 직접 승인**하므로 line 41과 양립한다. 사람이 읽을 수 있는 `5w4-` 접두사 덕에 URL만 봐도 유형 식별 가능. 10바이트 → base64url 14자, 전체 URL 약 45자로 카카오톡에 안전 | 경로 18종(9유형×2윙)만 존재 → 전부 `generateStaticParams`로 프리렌더. 가장 단순하고 가장 빠름 | 구현이 가장 쉽다. 인코딩/디코딩 코드 0줄 |

| **판정** | **채택** | **기각** | **기각** |

- A2 무효화 근거: AC-8이 "9유형 점수 막대그래프 표시"를, AC-9가 "새 브라우저에서 열면 **동일한** 결과 재현"을 동시에 요구한다. A2는 이 둘을 동시에 만족시킬 수 없다. (단, A2의 **빌드타임 프리렌더 이미지**라는 장점은 §3의 정적 OG 생성으로 흡수한다.)
- A3 무효화 근거: **스펙 line 41**("정적 경로 기반이어야 하며")이 공유 URL을 경로 기반으로 규정하므로 쿼리스트링 전용 설계는 선택지가 아니다. A1이 같은 조항에 걸리지 않는 이유는 **스펙 line 77**이 "정적 경로 + 쿼리 또는 base64url 세그먼트"를 별도로 승인하기 때문이며, A3은 경로 성분 없이 쿼리만으로 결과를 식별하므로 line 77의 허용 범위 밖이다. (이전 판의 "`next/og`가 쿼리스트링을 읽지 못한다"는 근거는 기술적으로 부정확하므로 철회한다.)

#### 결정 C — 90문항 조달 전략 (**최고 리스크 결정 — R1**)

| | C1. 공개 라이선스 척도 직접 채택 + 유형 매핑 | C2. 이론 문헌 기반 전량 자체 작성 | C3. 혼합 (확보 가능한 만큼 채택 + 나머지 자체 작성) |
|---|---|---|---|
| **Pros** | 문항 문구가 이미 검증·출판된 것이라 저작권 근거가 가장 단단하다. 저술 공수가 가장 적다 | 애니어그램 9유형 구성에 **정확히** 대응하는 문항을 설계할 수 있다. 유형당 10문항·facet 균형을 설계대로 달성 가능. 저작권 출처가 "이론 참조"로 단일하고 명확 | 확보 가능한 공개 문항의 공수 절감을 취하면서 빈 유형을 자체 작성으로 메운다 |

| **종결 근거 (Step 1 실측)** | IPIP 전체 문항 목록(849KB)과 모든 scale-label 인덱스를 **직접 grep한 결과 `enneagram` 일치 0건**. 공표된 IPIP→애니어그램 채점 키는 **존재하지 않는다**. 한국어·영어를 통틀어 문항 전문 + 9유형 채점 키가 공개되고 재사용이 허용되는 척도가 **확인되지 않았다**(`docs/sources.md` §3.2·§3.3·§3.6의 exhaustive negative search) | *Arica Institute, Inc. v. **판정 근거 (Step 1 완료 후 — 확정)**: Step 1의 조사(`docs/sources.md` §3)가 **사용 가능한 공개 라이선스 애니어그램 척도가 한국어·영어 어디에도 존재하지 않음**을 기록했다. 따라서 **C2를 최종 경로로 확정**한다. 이 판정은 더 이상 잠정이 아니며, Step 2 이후에 재개될 분기가 없다.

- **C1이 닫힌 방식**: 가정이 아니라 **증거**다. IPIP 5개 페이지(문항 풀 849KB 포함) 직접 grep → `enneagram` 0건. IPIP 문항 텍스트 자체는 퍼블릭 도메인이지만, **애니어그램 유형에 매핑하는 행위는 우리가 만들어내는 미검증 재해석**이므로 인용할 근거가 없다(D1 위반).
- **C3가 닫힌 방식**: 흡수 후보였던 **OEPS**(openpsychometrics.org)를 그 자체의 결함으로 기각했다 — ① v1 36문항 / v2 54문항으로 **90문항에 미달**(어느 경로로 가도 최소 36문항은 자체 작성해야 하므로 분량 문제를 해결하지 못한다) ② 라이선스 변종 미표기이나 형제 검사가 **CC BY-NC-SA 4.0** — **SA**면 우리가 추가 작성한 문항까지 동일 라이선스 공개 강제, **NC**면 수익화 차단 ③ 평균 **Cronbach's α ≈ 0.46**(허용 기준 0.70 미달), 애니어그램 애호가들의 **자기보고 유형에 준거 채점**되어 개발됨. 54문항을 얻기 위해 90문항 세트 전체의 라이선스 자유도를 넘기는 거래는 성립하지 않는다.
- **미해결 실마리 (판정에 영향 없음)**: 아랍어 45문항 척도(Alsoudi et al., 2025)는 **논문이 CC BY 4.0 gold OA**이나 부록에 문항이 인쇄됐는지 **미확인**이다. 확인되더라도 아랍어→한국어 번역이며 45문항이므로 C2 판정을 뒤집지 않는다. 기록만 남기고 추적하지 않는다.

- **중단 조건 (전역)**: Step 2.5 독립 리뷰에서 `verdict === 'rejected'`가 **90문항 중 20개 이상**이면 Step 3 이후를 시작하지 않고 중단한다. 이는 작성 방법론 자체가 상용 문항에 오염됐다는 신호이므로, 문항 재작성이 아니라 **작성 절차를 먼저 재설계**한다(참조 자료 차단 범위 재정의 후 Step 2 재실행).
- **중단 조건 (배치 단위)**: 전역 기준만으로는 늦다. Step 2는 유형 단위 9배치로 진행되므로(R12 완화), 한 배치가 **10문항 중 `rejected` 5개 이상**이면 그 시점에 나머지 배치를 시작하지 않고 즉시 중단한다. 한 배치의 5/10은 전역 20/90(≈22%)보다 훨씬 강한 오염 신호이며, 전역 기준을 기다리면 이미 오염된 절차로 최대 4~5배치를 더 작성한 뒤에야 멈추게 된다. 두 기준 중 **먼저 걸리는 쪽**이 발동하며, 발동 시 조치는 동일하다(작성 절차 재설계 → Step 2 재실행).
- **De-scope 조건**: 위 재실행 후에도 `clear` 문항이 90개에 미달하면 프로젝트를 배포하지 않는다. 문항 수를 줄여 배포하는 것은 AC-1 위반이므로 금지하며, 사용자에게 보고하고 범위 재협의한다.

## 3. ADR

### Decision

**결과 공유는 `/result/[code]` 단일 동적 경로로 구현한다.** `code = "{wingLabel}-{base64url(payload)}"` 형식이며, 예: `/result/5w4-AQoUHigyPEZQTA`.

- payload = 10바이트: `[version(1) , score1..score9(각 1바이트, 10~50)]` → base64url 14자.
- 결과 페이지 본문은 코드에서 디코드한 점수로 렌더한다 (서버 컴포넌트에서 디코드; 별도 데이터 조회 없음).
- **카드 컴포넌트는 하나다** (`components/ShareCardArt.tsx`). 이 컴포넌트는 두 시점에 렌더된다:
  - **빌드 타임 (주 경로)** — `scripts/gen-og.ts`가 18종 윙 라벨에 대해 `ImageResponse`로 `public/og/{wing}.png` (1200×630)를 생성한다. `generateMetadata`의 `og:image`는 이 **정적 파일**을 가리킨다. 크롤러는 런타임 이미지 생성 경로를 전혀 타지 않는다.
  - **런타임** — `app/result/[code]/card/route.tsx` (1080×1350)가 다운로드용 카드를 점수 막대까지 포함해 생성한다.
- OG 이미지의 정보 내용은 정확히 **윙 라벨 18종**으로 결정되므로(점수 막대는 OG 카드에 넣지 않는다) 빌드 타임 사전 생성이 손실 없이 가능하다.
- 두 경로 모두 같은 `ShareCardArt`를 쓰므로 P5는 유지된다.

### Drivers

D1(저작권 방어) · D2(링크 재현성 + 카카오톡 미리보기) · D3(인프라 단순성).

### Legal basis (문항 자체 작성 경로 — Step 1에서 확정)

***Arica Institute, Inc. v. Palmer*, 970 F.2d 1067 (2d Cir. 1992)** — 미국 제2순회항소법원은 애니어그램의 **기본 도형, 아홉 유형의 목록, 유형별 특성 서술이 저작권 보호 대상이 아니라고** 판시했다. 따라서 "유형 5의 핵심 두려움은 무능력에 대한 공포"와 같은 **이론적 구성개념은 자유롭게 사용할 수 있고**, 보호되는 것은 특정 저작물의 **표현**과 **검사 문항 텍스트**다. 한국 저작권법도 동일한 아이디어/표현 이분법을 따르며, 다음은 명확히 금지된다: 상용 검사 문항의 복제 / 번역·의역(제22조 2차적저작물 작성권) / 번역서 문장 전용.

이것이 **C2(이론 기반 전량 자체 작성)의 법적 근거**이며, 동시에 P2·Step 2.5·AC-14가 방어하는 대상의 경계를 정의한다 — 우리가 지켜야 하는 선은 "이론을 쓰지 않는 것"이 아니라 **"문항 텍스트를 베끼지 않는 것"**이다. 전문은 `docs/sources.md` §1.

### Alternatives considered

- **A2 유형 전용 정적 경로**: AC-8 + AC-9 동시 충족 불가로 기각. A2의 "빌드타임 고정 이미지" 장점은 정적 OG 사전 생성으로 흡수했다.
- **A3 쿼리스트링**: 스펙 line 41(경로 기반 공유 링크)에 위배되어 기각.
- **B1 DOM 캡처 / B2 Canvas 수작업**: 위 표의 무효화 근거대로 기각.
- **런타임 `opengraph-image.tsx`를 크롤러 주 경로로 두는 안**: 기각. OG 이미지의 정보 내용이 18종으로 유한하므로 런타임 생성은 불필요한 리스크(R5)만 추가한다.
- **C1 공개 척도 직접 채택 / C3 혼합**: Step 1의 실측 조사로 **증거상 종결**. 상세는 §2 결정 C.
- **체크섬 바이트 추가**: 기각(YAGNI). AC-9 참조.
- **`output: 'export'` 완전 정적 내보내기**: 런타임 `card` 라우트가 요청 시 렌더되는 함수이므로 양립 불가. **Vercel 기본 배포(정적 페이지 + 이미지 생성 함수)**를 "백엔드 없음"의 정의로 확정한다 — 이 함수는 상태를 갖지 않고 DB에 접근하지 않으며 사용자 데이터를 저장하지 않는다.

### Why chosen

A1 + B3(빌드타임 OG + 런타임 다운로드 카드) 조합만이 AC-8/9/10/11을 **동시에** 충족하면서 **새 런타임 의존성을 0개** 추가한다. 카드 렌더링 경로가 하나로 통일되어(P5) 디자인 변경 비용이 1곳에 머문다.

### Consequences

- `/result/[code]`는 빌드 타임 프리렌더 대상이 아니다 → 최초 방문 시 온디맨드 렌더 후 캐시. Vercel 기본 동작으로 충분하다.
- **이미지 라우트는 Node 런타임이다.** `export const runtime = 'nodejs'`를 **`app/result/[code]/card/route.tsx`에만** 적용한다. `scripts/gen-og.ts`는 Next 라우트 세그먼트가 아니라 독립 실행 스크립트이므로 같은 export가 아무 효과도 없다 — 그 파일에는 두지 않는다(대신 실행 러너를 Step 3.1에 명시한다). **Edge 런타임은 채택하지 않는다** — Edge에는 `fs`가 없고 `public/`을 읽을 수 없어 `VERCEL_URL` 기반 절대 URL fetch가 강제되는데, 이는 AC-12의 "`process.env` 런타임 참조 0건"을 정면으로 위반한다.
- **폰트 로드 경로는 번들러 추적 가능해야 한다.** `lib/fonts.ts`는 `readFileSync(new URL('./../assets/fonts/<subset>.ttf', import.meta.url))` 형태로 읽는다 — `process.cwd()` 문자열 결합은 Next의 output file tracing이 정적으로 따라갈 수 없어 Vercel 배포 번들에서 폰트 파일이 누락될 수 있다. 추가 안전장치로 `next.config.ts`에 `outputFileTracingIncludes: { 'app/result/[code]/card/route': ['./assets/fonts/**'] }`를 둔다. 이 둘 중 **최소 하나는 필수**이며, 효과는 로컬 `next dev`가 아니라 **Vercel 프리뷰 배포에서만** 확인된다(R13).
- **`metadataBase`는 하드코딩 상수다 — 그리고 항상 파싱 가능한 실제 URL이어야 한다.** `app/layout.tsx`가 `metadataBase: new URL('https://enneagram-test.vercel.app')` 형태의 상수를 설정한다. **`'https://<production-domain>'` 같은 플레이스홀더를 그대로 두면 안 된다** — `<`와 `>`는 WHATWG URL 파서의 금지 호스트 코드 포인트라 `new URL()`이 `TypeError: Invalid URL`을 던지고, 그 예외는 `app/layout.tsx` 모듈 평가 시점에 발생하므로 **첫 `npm run build`가 통째로 실패해 OG PNG가 0개 생성된다**. 따라서 도메인이 확정되기 전까지는 **Vercel이 부여한 프리뷰 호스트명을 잠정 상수(interim constant)로 넣어 둔다**(값은 유효하되 아직 최종이 아닐 뿐이다). 이유: `og:image`를 상대 경로 `/og/{wing}.png`로 두면 Next가 `metadataBase` 미설정 시 빌드 경고(`⚠`로 시작)를 내보내고, 그 경고는 AC-12의 줄머리 경고 grep에 그대로 걸린다. 표준 해법인 `new URL(process.env.VERCEL_URL ...)`은 AC-12의 `process.env` grep에 걸린다 — 즉 AC-10과 AC-12가 교착한다. 해소는 **환경변수 없는 하드코딩 상수**다.
  - AC-12의 "`process.env` 0건" 규칙은 두 가지 일을 겸하고 있다: ① 백엔드·런타임 상태가 없음을 증명한다 ② 무상태 **빌드타임 설정**까지 부수적으로 금지한다. ②는 의도된 목표가 아니라 규칙의 부작용이다. 따라서 **절대 URL이 필요한 모든 지점에서 "환경변수 대신 하드코딩 상수"가 표준 해소책**이며, 이 판단은 이후 유사 사례에도 그대로 적용된다.
  - 대가: 프로덕션 도메인이 코드에 고정되므로 **잠정 상수를 프로덕션 도메인으로 교체하는 것이 Step 6의 선행 조건**이다. 도메인이 바뀌면 코드 수정 + 재배포가 필요하다. 프리뷰 배포의 OG 이미지는 프로덕션 도메인을 가리키게 되지만, AC-10의 최종 확인은 프로덕션 URL에서 수행하므로 문제가 되지 않는다.
- **폰트 서브셋의 글리프 집합은 데이터에서 도출한다.** 임의의 KS X 1001 서브셋은 유형명 한 글자가 빠지면 두부(□)를 만든다. `data/types.ts` + `data/wings.ts` + 카드 고정 문구의 **모든 유니크 문자** ∪ 숫자 ∪ 라틴 기본 문자를 글리프 집합으로 계산해 `pyftsubset`에 넘긴다. 크기 목표(수백 KB)는 콜드 스타트 단축 목적이며, "Edge 번들 1MB 제한"이라는 이전 근거는 Node 런타임 채택으로 철회한다.
- **서브셋은 1회 도출로 끝나지 않는다 — 회귀 검사가 필요하다.** 글리프 집합은 Step 5.1에서 한 번 계산되지만 `assets/fonts/*`는 커밋된 바이너리이므로, 이후 유형명·윙 설명·카드 고정 문구를 한 글자라도 고치면 커밋된 서브셋이 **조용히 낡아** 18개 OG 이미지 전부에 두부(□)가 생긴다. 커밋된 `docs/og-sample.png`는 재생성되지 않으므로 이 회귀를 전혀 잡지 못한다. 따라서 `scripts/check-glyphs.ts`(또는 동등한 vitest 케이스)가 `data/types.ts` ∪ `data/wings.ts` ∪ 카드 고정 문구의 **모든 유니크 문자가 서브셋 폰트의 cmap 테이블에 존재하는지** 단언한다. 이 검사가 "글리프 집합을 데이터에서 도출한다"는 구조적 보장의 **실제 강제 지점**이므로, 사람이 부르는 V1·V3뿐 아니라 **`prebuild` 훅에 배선해 빌드가 강제로 통과시키게 한다**(`"prebuild": "tsx scripts/check-glyphs.ts && tsx scripts/gen-og.ts"`). V1·V3만으로는 사람이 검사를 건너뛴 채 두부 18장이 배포될 수 있다. 대가로 데이터 한 글자 수정이 빌드 실패로 나타나지만, 그것이 의도다.
- **satori는 woff2를 지원하지 않는다** → `.ttf`/`.otf`만 사용한다.
- **버전 바이트와 URL 영속성**: `encodeResult`는 점수만 저장하고 유형·윙은 디코드 시 재계산하며 접두사 일치를 검증한다. 따라서 **동점 규칙과 문항 세트는 URL 계약의 일부다.** 동점 규칙 또는 문항 세트를 변경하면 버전 바이트를 올려야 하며, **이는 기존 공유 링크를 무효화한다**(구버전 코드는 404). 선택: **(b) 콘텐츠 정정 시 링크 무효화를 수용한다.** 구 채점 로직을 영구 보존(a)하면 P3(인프라 최소)와 코드 단순성이 무너지고, 이 제품은 링크 영속성을 약속하지 않는다. 이것이 DB를 두지 않는 대가다. README에 명시한다.
- **접두사–점수 일치 검증만으로 무작위 14자 문자열은 거의 전부 거부된다** → 체크섬은 불필요하다(YAGNI). 단, 유효 범위 내 변조는 탐지되지 않는다(AC-9 참조).
- PNG 다운로드가 네트워크를 1회 왕복한다. 오프라인 동작은 Non-Goal이므로 수용한다.

### Step 0 — 최소 하네스 (툴체인만, UI·채점 없음)

**성격**: 설정 파일만. **UI 코드 0줄, 채점 로직 0줄.** "콘텐츠가 코드보다 먼저"(P1) 게이트는 그대로 유지된다 — 이 단계는 *제품 코드*가 아니라 *Step 2·2.5의 검사를 실행할 수 있게 하는 계측기*다. 이것 없이는 Step 2와 Step 2.5의 Done-when이 명목상 선언으로만 남는다.

**작업**

2. `data/questions.ts` — 90문항. 레코드 타입:

   type Facet = 'motivation' | 'fear' | 'behavior' | 'interpersonal' | 'stress';
   type CopyrightReview = {
     // 'pending' = Step 2 산출 시점의 플레이스홀더. AC-14가 'clear'만 통과시키므로

     // 커밋된 data/questions.ts에 최종 존속할 수 있는 값은 'clear' 뿐이다.
     //   'rewritten'/'rejected'는 처리 이력이므로 docs/item-review.md에만 남고,

     verdict: 'pending' | 'clear' | 'rewritten' | 'rejected';
     reviewedBy: string;   // Step 2.5 리뷰어 식별자. 같은 문항의 authoredBy와 달라야 한다.
     note: string;         // 판정 근거 1~2문장
   };
   type Question = {
     id: string; typeId: 1|2|3|4|5|6|7|8|9;
     text: string; sourceId: string;
     origin: 'adapted' | 'authored';
     facet: Facet;            // 조달 경로와 무관하게 필수

5. **문항 작성 규칙** (근거: `docs/sources.md` §5 — 조사에서 확인된 애니어그램 자기보고의 알려진 측정 편향에 대한 설계 대응).

   **기본 형식**: 한 문장, 1인칭 진술, 이중 질문 없음, 45자 이내 권장.

   **규칙 5-a — 역채점 문항 (묵종 편향 방어).** 유형당 **1~2문항**을 `reverse: true`로 작성한다.
   - **왜**: 애니어그램 문항은 인간 보편 경험을 담아 "그렇다"가 쉽게 나오고(바넘 효과와 결합), 전 문항 정채점이면 묵종 응답자의 **아홉 막대가 전부 40점대에 뭉친다**. 이는 원점수를 절대 규준처럼 읽히게 만들고 동점 빈도를 높인다(R7).
   - **어떻게**: 역채점 문항은 **부정문이 아니라 반대 방향의 긍정 진술**로 쓴다. 한국어 부정문 역문항("~하지 않는다")은 오독률이 높아 역채점의 이점을 상쇄한다.
     - ❌ `"나는 실수를 신경 쓰지 않는다"` (부정문)
     - ✅ `"결과가 조금 엉성해도 넘어가는 편이다"` (반대 방향 긍정 진술)
   - 역채점 문항도 facet 배치에 포함된다 — 별도 슬롯이 아니라 10문항 중 1~2개가 `reverse: true`인 것이다.

   **규칙 5-b — 상대·빈도 진술 (사회적 바람직성 + 절대 자기규정 방어).** 절대적 자기 라벨 대신 **다른 사람 대비 / 빈도** 표현을 우선한다.
   - ❌ `"나는 완벽주의자다"` (절대 자기 라벨 — 라벨 수용 여부를 묻게 된다)
   - ✅ `"다른 사람들보다 세부 오류가 먼저 눈에 들어오는 편이다"`
   - 유형당 **최소 3문항**은 Palmer의 **주의 초점(focus of attention)** 형식(`palmer-1988`)으로 쓴다 — 동기 진술("나는 ~를 원한다")은 사회적 바람직성에 취약한 반면 주의 초점 문항은 훨씬 덜 취약하다.

   **규칙 5-c — 시간 프레임 고정 (유형 vs. 기분·상황 혼동 방어).** **모든 문항**에 `"평소에"` / `"지난 몇 년간 대체로"` 같은 시간 프레임을 넣는다.
   - **왜**: 시간 프레임이 없으면 문항이 **특성이 아니라 현재 기분**을 포착한다. 이 오염은 **유형 4·6에서 가장 심각하다** — 최근 실직·이별을 겪은 응답자가 우울·불안 **상태** 때문에 4번으로 나오는 식이다.
   - 현재 시제 감정 문항(`"요즘 나는 외롭다"`)은 **전면 배제**한다.

   **규칙 5-d — Naranjo 용어의 중립화.** 열정(passion)/고착 용어를 그대로 문항화하지 않는다. 덕목 언어도 악덕 언어도 아닌 **중립적 행동 기술**로 옮긴다.
   - ❌ `"나는 게으르다"` → ✅ `"해야 할 일을 알면서도 덜 중요한 일로 시간을 보낼 때가 있다"`

   **규칙 5-e — 평균 발달 수준 기준.** 문항은 Riso & Hudson의 **평균 수준(Levels 4–6)** 기술에 맞춰 쓴다. 불건강 수준 기술을 문항화하면 일반 응답자 대부분이 부정 응답해 변별력이 소실된다.

6. **facet 충돌 쌍 대조 검수 (배치 작성 후 필수)** — `docs/sources.md` §5가 식별한 **고충돌 쌍 7개**에 대해, 두 유형의 문항을 **나란히 놓고 읽으며** 서로 다른 것을 재고 있는지 확인하고 겹치는 문항을 차별화한다.

   | 충돌 쌍 | 겹치는 축 |
   |---|---|
   | 1–4 | 자기비판 |
   | 2–9 | 타인 동화 |
   | 3–1 | 높은 기준 |
   | 5–9 | 철수 |
   | 6–1 | 문제 발견 |
   | 7–9 | 회피 방향 |
   | 8–2 | 보호/돌봄 |

   - **왜 이 단계가 따로 있는가**: 변별력 부족은 요인 구조가 9개로 재현되지 않는 문제(`hook-2021`·`newgent-2004`)를 **우리 스스로 재생산하는** 가장 흔한 경로다. 그리고 이 검수는 **싸다** — 쌍당 20문항을 나란히 읽는 것뿐이다.
   - **실행 시점**: 9배치가 모두 끝난 뒤 한 번에. 어느 배치든 쌍의 한쪽만 존재하면 대조가 불가능하므로 배치 중간에는 할 수 없다.
   - **산출**: 차별화를 위해 수정한 문항이 있으면 그 사실을 **Step 2.5 리뷰어에게 전달하지 않는다**(리뷰어 입력 범위는 문항 텍스트 + `typeId` + 이론 출처로 고정 — Step 2.5 참조). 대신 `rationale` 필드에 그 문항이 **왜 인접 유형이 아니라 이 유형을 재는지**를 명시한다.
   - **판정**: 쌍 하나라도 "두 유형의 문항이 사실상 같은 것을 재고 있다"가 해소되지 않으면 해당 facet 슬롯을 재작성한다. 미해소 상태로 Step 2를 닫지 않는다.

**배치 전략 (R12 완화)**: 유형 단위 9배치로 진행한다. 배치당 산출물 = 해당 유형의 10문항 + 유형 서술 1건 + 윙 서술 2건. 각 배치 완료 시 `data/` 파일에 커밋해 부분 진행이 표현되게 한다. **`authoredBy`는 그 배치를 수행한 작성자 식별자로 채운다** — 배치마다 값이 다를 수 있으므로 전역 상수를 쓰지 않는다.

`copyrightReview`는 TS 필수 필드라 비워둘 수 없으므로, Step 2 산출 시점에는 **`{ verdict: 'pending', reviewedBy: '', note: '' }`** 플레이스홀더를 넣고 Step 2.5에서 실제 값으로 교체한다. 이 플레이스홀더가 주는 **실제 보장**은 다음과 같다: AC-14는 `verdict === 'clear'`를 요구하는데 플레이스홀더는 `'pending'`이므로, **리뷰어가 각 문항의 `verdict`를 직접 판정해 덮어쓰지 않는 한 AC-14는 절대 통과하지 않는다.** 이전 판처럼 플레이스홀더를 `verdict: 'clear'`로 두면 리뷰어가 `reviewedBy`와 `note`만 채우고 `verdict`를 손대지 않아도 통과해 버려, "검토된 clear"와 "손대지 않은 기본값 clear"가 데이터상 구별되지 않는다 — 즉 게이트가 fail-open이 된다. `'pending'` 기본값은 이를 fail-closed로 뒤집는다.

**Files**: `data/sources.ts`, `data/questions.ts`, `data/types.ts`, `data/wings.ts` (전부 신규)

**Done when**: Step 0의 하네스로 **실제 실행한** `npx tsc --noEmit` 0 에러 + `npx vitest run data/questions.test.ts`의 **AC-1·AC-2·AC-8(데이터) 단언이 통과**한다(AC-3·AC-14 단언은 이 시점에 여전히 실패하며 둘 다 Step 2.5에서 닫힌다. **단, 실패 지점은 서로 다르다**: AC-14는 90문항의 `verdict`가 전부 `'pending'`이라 전면 실패하는 **주 fail-closed 게이트**이고, AC-3은 ①비복제 진술·③5라벨 섹션 파싱이 Step 1에서 이미 통과하므로 **`## 저작권 리뷰 절차` 섹션의 판정 분포 기록 단언 하나만** 실패한다 — 그 분포는 Step 2.5를 수행해야만 존재하는 값이다). 구체적으로: 90/9/18 개수 정확, 모든 `sourceId`가 `sources.ts`에 존재(**id 집합이 Step 1의 확정 7건과 정확히 일치**), 유형별 facet 분포 각 2개, **유형별 `reverse: true` 개수가 1 이상 2 이하**, `origin`·`rationale`·`authoredBy` 비어있지 않음, `types.ts`의 4개 서술 필드가 9유형 전부에서 비어있지 않음. 또한 **facet 충돌 쌍 7개의 대조 검수(작업 6)가 수행됐다** — 이 항목은 테스트로 강제되지 않는 사람 검수이므로, 수행 사실과 차별화한 문항 목록을 Step 2.5의 `docs/item-review.md`가 아니라 **커밋 메시지 또는 `rationale` 필드**에 남긴다. → **AC-1, AC-2, AC-8(데이터 측면)**

**Rollback / stop condition**: 특정 유형의 10문항을 이론 근거만으로 작성할 수 없다고 판단되면(근거 문헌 부족), 그 유형 배치를 중단하고 Step 1로 되돌아가 해당 유형의 출처를 보강한다. 부분 커밋 구조 덕분에 되돌리는 범위는 해당 유형 배치 1개다.

### Step 2.5 — 문항 독립 저작권 리뷰 패스 (**P2의 실제 강제 지점**)

**성격**: 리뷰 + 문서 작성. 새 문항 작성은 재작성 시에만.

**리뷰어 분리 규칙 (open question #2의 확정 해소)**
- 작성 패스와 리뷰 패스는 **별도 에이전트 컨텍스트**에서 실행한다.
- 리뷰어에게는 **문항 텍스트 + `typeId` + 이론 출처만** 전달한다. **작성 과정의 대화 기록(authoring transcript)은 전달하지 않는다** — 작성 근거를 본 리뷰어는 "이론에서 나왔다"는 서사를 그대로 수용하게 되어 독립성이 사라진다.
- 리뷰어의 식별자가 `copyrightReview.reviewedBy`에 기록된다. 작성자 식별자와 같으면 AC-14가 실패한다.

**작업**
1. 리뷰어가 90문항을 **전수** 판정한다. 판정 질문: *"이 문장이 RHETI·WEPSS·Essential Enneagram Test 등 상용 검사 문항의 번역 또는 변형으로 보이는가?"*
2. 판정 결과를 `copyrightReview`에 기록한다.
   - `clear` — 독립 작성으로 판단. 그대로 유지.
   - `rewritten` — 의심되어 **폐기 후 재작성**함. (수정하지 않는다. 수정은 원문 흔적을 남긴다.) 재작성된 문항은 다시 리뷰를 받아 최종 `clear`가 되어야 한다.
   - `rejected` — 폐기하고 대체 문항을 작성한다. 폐기 사실과 사유를 `docs/sources.md`에 기록한다.
3. `docs/item-review.md`를 작성한다: 리뷰 일자, 리뷰어 식별자, 리뷰어에게 제공된 입력 범위(문항 텍스트·typeId·이론 출처), 판정 분포(clear/rewritten/rejected 개수), `rejected` 목록과 사유, 재작성 이력.
4. `docs/sources.md`의 `## 저작권 리뷰 절차` 섹션을 실제 수행 내용으로 채운다 — **반드시 판정 분포(`clear`/`rewritten`/`rejected` 각 개수, 최종 `clear` = 90)를 포함한다.** AC-3의 종결 단언이 이 수치를 읽는다.

**Files**: `docs/item-review.md` (신규), `data/questions.ts` (수정 — `copyrightReview` 실값), `docs/sources.md` (수정)

**Done when**: `npx vitest run data/questions.test.ts`가 **전부 통과**한다 — 90문항 전부 최종 `verdict === 'clear'`, 문항별 `copyrightReview.reviewedBy !== authoredBy`, `note` 비어있지 않음, 그리고 AC-3의 `docs/sources.md` 섹션 파싱 단언 통과. `docs/item-review.md`가 위 5개 항목을 포함하며 섹션 파싱 단언(§7 V1)을 통과한다. → **AC-3, AC-14**

**Rollback / stop condition**: 결정 C의 두 중단 조건 중 **먼저 걸리는 쪽**이 발동한다 — ① 한 배치(10문항)에서 `rejected` **5개 이상** ② 전체 초기 판정에서 `rejected` **20개 이상**. 둘 중 하나라도 걸리면 개별 재작성으로 수습하지 않는다. Step 2 전체를 중단하고 작성 절차(참조 자료 차단 범위)를 재설계한 뒤 Step 2를 재실행한다. 재실행 후에도 `clear` 90개에 도달하지 못하면 결정 C의 de-scope 조건에 따라 배포하지 않고 사용자에게 보고한다.

### Step 3 — 프로젝트 스캐폴딩 + 채점 엔진 + 코드 인코딩 (테스트 우선)

   - Next 메이저 버전은 Step 0에서 고정한 값을 그대로 쓴다(생성기가 emit하는 버전에 맡기지 않는다) — 린트 CLI와 런타임 API가 메이저 간 달라지기 때문이다. 런타임 `dependencies`는 `next`, `react`, `react-dom` 만.
   **devDependencies 전체 목록** (devDeps는 런타임 의존성이 아니므로 AC-12의 3개 상한에 포함되지 않는다 — AC-12는 `dependencies`만 센다):

   - 타입·린트·스타일: `typescript`, `@types/node`, `@types/react`, `@types/react-dom`, `tailwindcss`, `eslint`, `eslint-config-next`

**Files**: `next.config.ts`, `postcss.config.mjs`, `eslint.config.mjs`, `lib/types.ts`, `lib/scoring.ts`, `lib/code.ts`, `lib/scoring.test.ts`, `lib/code.test.ts` (전부 신규); `package.json`·`tsconfig.json`·`vitest.config.ts` (Step 0에서 생성 — 여기서는 수정)

### Step 5 — 결과 페이지 + OG 이미지 + PNG 카드 (한글 폰트 검증 먼저)

**작업**
1. **먼저 폰트부터 검증한다** (최대 구현 리스크):
   - **대역 외 선행 조건**: `pyftsubset`은 npm 패키지가 아니라 **Python `fonttools`** 의 CLI다. 착수 전에 `pip install fonttools` (또는 `brew install fonttools`)로 설치하고 `pyftsubset --help`가 동작함을 확인한다. 이는 프로젝트 의존성이 아닌 **작성자 로컬 환경 요건**이며, 산출물(`assets/fonts/*.ttf`)만 저장소에 커밋되므로 Vercel 빌드 환경에는 Python이 필요 없다.

2-1. `components/ResultView.tsx` — **순수 프레젠테이션 컴포넌트**(props-in, 비동기 아님, 데이터 조회 없음). 주유형 상세 4섹션, 윙 설명 **+ `이론적 해석` 마커**, 9유형 **상대 비율 막대 + 원점수 + 1–2위 점수차**, `isAmbiguous` 안내, **면책 고지**를 렌더한다.

   **분리 이유**: AC-8의 렌더 측면은 컴포넌트 렌더 테스트로 닫는데, async 서버 컴포넌트는 `@testing-library/react`로 그대로 마운트할 수 없다. 테스트가 붙잡을 수 있는 동기·순수 컴포넌트가 하나 필요하며 그것이 `ResultView`다.

   - **실행 러너는 `tsx`** 다(Step 3.1). `package.json`에 `"prebuild": "tsx scripts/check-glyphs.ts && tsx scripts/gen-og.ts"` — 글리프 검사가 OG 생성 앞에 묶여 있으므로 **낡은 서브셋은 빌드를 실패시킨다**(Step 3.1의 트레이드오프 주석 참조). Node 내장 타입 스트리핑은 JSX를 처리하지 못하므로 러너 없이는 이 파일이 실행되지 않는다.

   - `export const runtime = 'nodejs'`를 **이 파일에 두지 않는다** — Next 라우트 세그먼트 설정이라 독립 스크립트에서는 아무 효과가 없다.

   - `?dl=1` 유무는 캐시 키에 영향을 주므로 `Vary` 고려 불필요(쿼리스트링이 URL의 일부다).
6. `components/ScoreBars.tsx`, `components/ShareActions.tsx` — 링크 복사 + **3단 저장 폴백**:
   - **① Web Share**: `navigator.canShare({ files })` → `navigator.share({ files })`. Web Share API는 실제 `File` 객체를 요구하므로, 이 단계 **안에서는** `fetch('/result/[code]/card?dl=1')` → `res.blob()` → `new File([blob], 'enneagram-<code>.png', { type: 'image/png' })` 를 **수행한다**. 이 경로 없이는 tier 1을 구현할 방법이 없다.
   - **② 앵커 다운로드**: `<a href="/result/[code]/card?dl=1" download="enneagram-<code>.png">`. 동일 출처 URL을 직접 가리키며, 파일명은 `download` 속성이 나른다.
   - **③ 인라인 이미지**: 페이지에 `<img src="/result/[code]/card">`(맨 URL, 인라인 헤더)를 렌더하고 "길게 눌러 저장" 안내.
   - **금지 사항의 정확한 범위**: 금지되는 것은 **blob URL 다운로드**, 즉 `URL.createObjectURL(blob)`을 `<a download>`의 `href`로 쓰는 패턴이다 — iOS Safari에서 실패하는 것이 이 조합이다. `fetch`→`blob`→`File` 자체는 tier 1에서 **허용**된다(다운로드가 아니라 공유 시트에 넘길 객체를 만드는 용도). 이전 판의 "`fetch`→`blob` 단계는 두지 않는다"는 범위를 잘못 잡아 tier 1을 구현 불가능하게 만들었으므로 위와 같이 정정한다.

**Files**: `app/result/[code]/page.tsx`, `app/result/[code]/card/route.tsx`, `app/not-found.tsx`, `components/ResultView.tsx`, `components/ShareCardArt.tsx`, `components/ScoreBars.tsx`, `components/ShareActions.tsx`, `components/__tests__/result.test.tsx`, `scripts/gen-og.ts`, `scripts/check-glyphs.ts`, `lib/fonts.ts`, `docs/licenses.md`, `assets/fonts/*`(커밋), `public/og/*`(**빌드 생성물 — `.gitignore` 대상, 커밋하지 않는다**; Step 0 항목 5), `docs/og-sample.png`(커밋 — 한글 렌더 증거) (전부 신규); `package.json`(`prebuild` 추가), `next.config.ts`(`outputFileTracingIncludes`) 수정

### Step 6 — 빌드 클린업 + Vercel 배포 + 스모크 검증

**선행 조건 (blocking)**: **`vercel --prod` 전에 `app/layout.tsx`의 잠정 상수를 프로덕션 도메인으로 교체해야 한다.** Step 4.1에서 넣은 값은 Vercel 프리뷰 호스트명(예: `https://enneagram-test.vercel.app`)이며, 이는 *유효하지만 최종이 아닌* 값이다. 교체하지 않고 프로덕션 배포하면 OG 이미지 절대 URL이 프리뷰 호스트를 가리켜 AC-10이 닫히지 않는다. **도메인 확정 → `layout.tsx` 상수 교체 → `npm run build` 재실행(OG PNG 재생성) → `vercel --prod`** 순서를 지킨다.

**작업**
1. `next build` 출력의 **모든 경고를 실제로 제거**한다(경고 억제 설정으로 숨기지 않는다). `metadataBase` 미설정 경고가 여기서 나오면 Step 4.1이 덜 끝난 것이다.
2. AC-12의 **직접 속성 검사**를 수행한다(§7 V3). 의존성 개수는 보조 지표로만 확인한다.
3. Vercel 배포 (프레임워크 자동 감지, 환경변수 0개).

### 저작권 게이트 (CRITICAL — 이전 판에서 fail-open이었다)

1. **`Question`에 `authoredBy: string` 필드 신설.** 이전 판의 AC-14는 `reviewedBy !== AUTHOR_ID`를 단언했으나 **`AUTHOR_ID`는 계획 어디에도 정의되지 않았고**, `Question`에 작성자 필드도 없었다. 게다가 작성이 9배치로 나뉘므로 전역 상수 하나로는 애초에 옳지 않다. AC-14의 단언을 **문항별 `copyrightReview.reviewedBy !== q.authoredBy`** 로 교체하고 V1의 `AUTHOR_ID` 참조를 삭제했다.
2. **플레이스홀더 `verdict`를 `'clear'` → `'pending'` 으로 교체하고 `verdict` 유니온에 `'pending'`을 추가.** 이전 판은 기본값이 `'clear'`이고 가드가 `reviewedBy !== 'PENDING'` 뿐이라, 리뷰어가 이름과 메모만 채우고 `verdict`를 손대지 않으면 **검토되지 않은 `'clear'`가 그대로 통과**했다 — 진짜 판정과 데이터상 구별 불가능. 이제 AC-14의 `=== 'clear'`가 **명시적 판정을 강제**한다(fail-closed). 커밋된 데이터에 존속 가능한 값은 `'clear'` 뿐이며 `'rewritten'`/`'rejected'`는 `docs/item-review.md`의 이력으로만 남는다는 점을 타입 주석에 명시했다.
3. Step 2 배치 전략의 "플레이스홀더 상태로는 AC-14가 닫히지 않는다"는 문장을 **실제 보장을 서술하는 문장**으로 교체했다(무엇이 왜 막히는지).

### E2 — 결정 C 확정
**잠정 → 확정.** C2(이론 기반 전량 자체 작성)가 최종 경로이며 재개될 분기가 없다.

- **C3는 재료 부재로 소멸했다** — 흡수 후보였던 **OEPS**를 자체 결함으로 기각(36/54문항으로 분량 미달 / CC BY-NC-SA 추정의 SA·NC 비용 / Cronbach's α ≈ 0.46 + 애호가 자기보고 준거 채점). 흡수 대상이 0건이면 C3는 C1과 같은 자리로 붕괴한다.
- 옵션 표는 **삭제하지 않고 유지**했다 — 기각된 선택지와 그것을 닫은 증거가 이 문서의 산출물이다. 각 열에 **`종결 근거 (Step 1 실측)`** 행을 추가했다.
- ADR에 **Legal basis** 절을 신설: *Arica Institute, Inc. v. Palmer*, 970 F.2d 1067 (2d Cir. 1992) — 애니어그램의 도형·유형 목록·특성 서술은 저작권 보호 대상이 아니다. 이것이 자체 작성 경로의 법적 근거이며, 동시에 **지켜야 할 선이 "이론을 쓰지 않는 것"이 아니라 "문항 텍스트를 베끼지 않는 것"** 임을 정의한다.

### E3 — 역채점 문항 도입 (채점에 영향)
**이전 계획은 90문항 전부 정채점이었다.** 애니어그램 문항은 인간 보편 경험을 담아 "그렇다"가 쉽게 나오고(바넘 효과 결합), 묵종 응답자의 **아홉 막대가 전부 40점대에 뭉친다**. 이는 R7의 동점 빈도 추정을 낙관적으로 만들고 원점수를 절대 규준처럼 읽히게 한다.

### E4 — 윙을 "이론적 해석"으로 라벨링 (결과 화면에 영향)
Hook et al. (2021), **104개 독립 표본 체계적 문헌고찰**: **윙과 통합/분열 화살표에 대한 실증 근거가 거의 없고**, 요인분석은 일관되게 **9개보다 적은 수의 요인**을 산출한다.

### E5 — `docs/sources.md`를 파일 인벤토리에 배선
- Step 1 Files를 "신규 → **신규 — 작성 완료**"로.
- **AC-3 단언의 현재 상태를 실측으로 확인**해 Step 1에 기록했다. 계획이 이미 기술하던 분할과 파일이 **실제로 일치한다**: ✅ 통과 예정 = 비복제 진술(선두 30줄 내 RHETI + WEPSS) · `## 저작권 리뷰 절차` 섹션 존재 · source id 표제와 일치하는 7개 `##` 섹션 전부에 정준 라벨 5종 + 값 비어있지 않음. ❌ 의도적 실패 = **판정 분포 기록 단언 하나뿐** (§4.2가 `(미수행)`). 이 실패는 Step 2.5에서 닫힌다.
- **source id 7건 확정**: `riso-hudson-personality-types`, `riso-hudson-wisdom`, `palmer-1988`, `naranjo-1994`, `chestnut-2013`, `hook-2021`, `newgent-2004`. Step 2 작업 1에 각 id의 용도 표를 넣고, `data/sources.ts`의 id 집합이 이것과 **정확히 일치**해야 함을 Step 2 Done-when과 V1에 단언으로 추가했다. 새 출처는 **문서에 5라벨 `##` 섹션을 먼저 만든 뒤** 코드에 추가한다.

### E6 — facet 충돌 쌍 대조 검수를 Step 2의 필수 하위 작업으로
`docs/sources.md` §5가 식별한 고충돌 쌍 **7개**(1–4 자기비판, 2–9 타인 동화, 3–1 높은 기준, 5–9 철수, 6–1 문제 발견, 7–9 회피 방향, 8–2 보호/돌봄)에 대해, 작성 후 두 유형의 문항을 **나란히 놓고 읽으며 차별화**한다.
- **왜**: 변별력 부족은 "요인 구조가 9개로 재현되지 않는" 문제를 **우리 스스로 재생산하는** 가장 흔한 경로다. 그리고 이 검수는 **싸다**.
- **실행 시점**: 9배치가 전부 끝난 뒤 한 번에 (쌍의 한쪽만 있으면 대조 불가).
- **산출**: 리뷰어 독립성을 지키기 위해 수정 이력을 Step 2.5 리뷰어에게 전달하지 **않고**, 대신 `rationale`에 "왜 인접 유형이 아니라 이 유형을 재는지"를 명시한다.
- **판정**: 미해소 쌍이 하나라도 남으면 Step 2를 닫지 않는다.
